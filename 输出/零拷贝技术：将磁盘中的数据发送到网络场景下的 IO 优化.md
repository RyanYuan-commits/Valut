## 1	传统 IO 的痛点

如果要实现将磁盘中的数据发送到网络中，在传统的 I/O 模型下，会涉及四次上下文切换和四次数据拷贝：

- 程序发起 `read` 系统调用，从用户态**切换**到内核态；DMA 将数据从磁盘**拷贝**到内核缓冲区；
- 数据从内核缓冲区**拷贝**到应用缓冲区，上下文**切换**回用户态；
- 程序发起 `send` 系统调用，从用户态**切换**到内核态，CPU 将应用缓冲区中的数据**拷贝**到内核空间的 socket buffer；
- 随后 DMA 将数据从 socket buffer **拷贝**到网卡准备发送，上下文**切换**回用户态。

## 2	零拷贝的实现方式

### 2.1	mmap 技术

mmap（memory mapping）技术将内核缓冲区中的一段内存映射到用户空间，数据通过 DMA 从磁盘拷贝到内核缓冲区后，应用程序就可以操控着部分数据，省去了从内核缓冲区拷贝到用户缓冲区的损耗；

使用 mmap 优化后，将磁盘中的数据发送到网络中的场景的损耗变为了四次上下文切换和三次数据拷贝，优化掉了一次 cpu 参与的拷贝。

### 2.2	sendfile 技术

**早期 sendfile**：调用 `sendfile()`，产生一次内核态切换。DMA 将磁盘数据拷贝到内核读取缓冲区。然后，cpu 直接把数据从读取缓冲区拷贝到 socket 缓冲区。最后 DMA 把数据拷贝到网卡。

**完善版 sendfile**：从 Linux 2.4 开始，如果网卡支持 SG-DMA 技术，可以省略掉最后一次 cpu 拷贝

- DMA 将磁盘数据放入内核缓冲区；
- CPU **不再搬运数据**，而是仅仅把数据的**描述符**（包含内存地址和长度信息）追加到 Socket 缓冲区；
- 网卡的 SG-DMA 引擎根据描述符，直接去内核缓冲区将数据收集并拷贝到网卡发送；
- 只需要进行 2 次上下文切换、2 次 DMA 拷贝，这就是狭义上最完美的“零拷贝”。
