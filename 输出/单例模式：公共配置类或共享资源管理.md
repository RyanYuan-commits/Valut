## 1	使用场景

系统的配置类，负责在系统启动时读取配置文件，重新读取需要耗费大量的 I/O 资源，可以采用单例模式优化；

管理昂贵的共享资源，如连接池、线程池，可以使用单例模式。

## 2	代码实现

```java
public class Main {

    public static void main(String[] args) {
        SingletonDCL instance1 = SingletonDCL.getInstance();
        SingletonInner instance2 = SingletonInner.getInstance();
    }

    /**
     * 通过双重检查锁实现单例对象的安全创建
     */
    static class SingletonDCL {

        private static volatile SingletonDCL instance;

        private SingletonDCL() {
            if (instance != null) {
                throw new RuntimeException("禁止通过反射创建实例");
            }
        }

        public static SingletonDCL getInstance() {
            if (instance == null) {
                synchronized (SingletonDCL.class) {
                    if (instance == null) {
                        instance = new SingletonDCL();
                    }
                }
            }
            return instance;
        }

    }

    /**
     * 通过静态内部类实现单例对象的安全创建
     */
    static class SingletonInner {

        private SingletonInner() {}

        private static class SingletonHolder {
            private static final SingletonInner INSTANCE = new SingletonInner();
        }

        public static SingletonInner getInstance() {
            return SingletonHolder.INSTANCE;
        }
    }

}
```

## 3	单例模式带来的隐性问题

会带来隐形的依赖关系，一般一个类的依赖关系通过构造方法就可以看出，但是在单例模式中，类在任何时间都可以通过调用 `getInstance()` 方法获取实例，会导致依赖关系比较混乱；

单例的全局依赖，可能会影响单元测试的效果，若测试 A 修改了全局依赖的状态，可能会导致测试 B 出现问题；
