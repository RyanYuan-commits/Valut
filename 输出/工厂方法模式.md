## 1	适用场景

**核心思想**：定义一个==创建==对象的接口，让实现这个接口的类决定创建哪个实例。

- 当你在编写代码时，**无法预见未来需要创建哪些具体类的对象**，或者你希望**为未来的扩展留出接口**时；
- 复杂对象的创建方式需要被隐藏，降低外部使用的难度。

## 2	代码案例

**场景**：代码中需要支持不同的支付方式；

```java
public class PaymentService {
    // 业务处理方法
    public void processPayment(String paymentType, double amount) {
        if ("WeChat".equals(paymentType)) {
            WeChatPayment wxPay = new WeChatPayment();
            // 可能还有一堆微信支付的初始化参数...
            wxPay.pay(amount);
        } else if ("Alipay".equals(paymentType)) {
            AliPayment aliPay = new AliPayment();
            // 可能还有一堆支付宝的初始化参数...
            aliPay.pay(amount);
        } else {
            throw new IllegalArgumentException("不支持的支付方式");
        }
    }
}
```

如果使用 `if-else` 实现，支付方式的选择与支付代码糅合在一起，且后续拓展需要修改原代码。

```java
// ====== 定义产品的实现 ======
public interface Payment {
    void pay(double amount);
}

public class WeChatPayment implements Payment {
    @Override
    public void pay(double amount) {
        System.out.println("使用微信支付了: " + amount + " 元");
    }
}

public class AliPayment implements Payment {
    @Override
    public void pay(double amount) {
        System.out.println("使用支付宝支付了: " + amount + " 元");
    }
}

// ====== 定义工厂接口 ======
public interface PaymentFactory {
    Payment createPayment();
}

public class WeChatPaymentFactory implements PaymentFactory {
    @Override
    public Payment createPayment() {
        // 这里可以隐藏复杂的微信配置加载逻辑
        return new WeChatPayment();
    }
}

public class AliPaymentFactory implements PaymentFactory {
    @Override
    public Payment createPayment() {
        // 这里可以隐藏复杂的支付宝配置加载逻辑
        return new AliPayment();
    }
}
```

```java
public class Client {
    public static void main(String[] args) {
        // 实际开发中，这个 factory 通常通过配置文件、依赖注入或反射动态获取
        // 比如用户选择了微信支付，系统就塞一个 WeChatPaymentFactory 进来
        PaymentFactory factory = new WeChatPaymentFactory(); 
        
        // 核心业务逻辑：我只要一个支付对象，你怎么造的我不管
        Payment payment = factory.createPayment();
        payment.pay(100.0);
    }
}
```

客户端代码核心业务逻辑不依赖工厂实现，`new WeChatPaymentFactory()` 也可以抽离出单独的类，根据传入的参数决定实例化的类。
