## 1	核心组件扮演的角色

网卡：负责将光电信号转化为数据包，并和内存进行数据交互；

DMA：主板上的一块芯片，专门负责硬件和内核内存之间的数据交互，目的是解放 CPU，让其更专注于计算类任务；

内核缓冲区：对于网络 I/O 来说，指的是 TCP/IP 技术栈维护的 socket 发送与接收缓冲区；对于磁盘 I/O 来说，指的是页缓存；

用户缓冲区：应用程序申请的内存空间。

## 2	接收网络数据场景剖析

### 2.1	数据从网卡到内核

这部分工作由硬件和操作系统自动完成，**与应用程序无关**。

- 数据包通过网络光纤/网线到达服务器的**网卡**；
- 网卡通过 **DMA** 直接将数据包拷贝到内核空间的环形缓冲区 (Ring Buffer) 中，这个过程不需要 CPU 的参与；
- 数据拷贝完成后，网卡向 CPU 发送一个硬件中断信号，告诉 CPU：“数据到了，赶紧处理！”；
- CPU 暂停手头工作，触发软中断。Linux 的 TCP/IP 协议栈开始工作，剥离数据包的以太网头、IP 头、TCP 头，进行校验；
- 协议栈将最终的应用层有效负载存放入该连接对应的接收缓冲区中。

### 2.2	数据从内核到应用

java 线程调用 `read()`，虚拟机会向操作系统发起一个 `read` 系统调用，此时，当前线程会从用户态切换到内核态。

如果此时接收缓冲区**没有数据**，BIO 模式下，java 线程就会在这里阻塞，交出 CPU 执行权；NIO 模式下则会直接返回一个标识，告诉你没数据。
如果接收缓冲区**有数据**，**CPU** 会介入，将数据从内核的 Socket 接收缓冲区拷贝到用户空间的缓冲区。

拷贝完成后，`read` 调用返回，发生第二次上下文切换，Java 代码拿到数据，继续执行业务逻辑。

在传统的 Read 过程中，发生了一次 DMA 拷贝，一次 CPU 拷贝，以及两次上下文切换。
